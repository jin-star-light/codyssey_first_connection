# 제철한입 웹 서비스 설계

## 1. 목적과 대상

제철한입은 사용자가 날짜를 입력하면 그 시기에 한국에서 쉽게 구할 수 있는 과일 3종을 추천하는 반응형 웹 서비스다. 건강한 간식과 장보기에 관심 있는 일반 사용자가 복잡한 검색 없이 제철 과일의 특징과 활용법을 확인하도록 돕는다.

핵심 가치는 다음과 같다.

- 입력한 날짜를 월 단위 제철 기준으로 해석한다.
- 과일 3종과 제철 이유, 맛·영양 특징, 잘 고르는 법, 보관법, 간단한 레시피를 제공한다.
- 검증 가능한 월별 후보 데이터와 AI 설명 생성을 조합해 결과의 안정성과 유용성을 함께 확보한다.

## 2. 범위

### 포함

- 순수 HTML, CSS, JavaScript로 만든 단일 페이지 웹 서비스
- 메뉴로 이동할 수 있는 홈, AI 과일 추천, 제철 캘린더, 이용 안내·FAQ 섹션
- Vercel Python Serverless Function 기반 추천 API
- Codyssey OpenAI 호환 API 연동
- 모바일, 태블릿, 데스크톱 반응형 화면
- 빈 입력, 잘못된 날짜, API 오류, 지연·타임아웃 안내
- README와 서비스 기획서
- 배포에 필요한 환경변수와 Vercel 설정 안내

### 제외

- 로그인, 데이터베이스, 추천 이력 저장
- 외부 농산물 시세·유통 API 연동
- 자동화 테스트 코드와 테스트 프레임워크
- 실제 운영 배포와 배포 URL 입력은 사용자 계정 연결이 필요한 후속 작업으로 남긴다.

## 3. 사용자 흐름

1. 사용자가 홈에서 서비스 목적을 확인하고 추천 섹션으로 이동한다.
2. 날짜 입력 필드에서 원하는 날짜를 선택한다.
3. 추천 버튼을 누르면 로딩 상태와 진행 안내가 표시된다.
4. 서버가 해당 월의 제철 과일 후보를 찾고 AI에 설명 생성을 요청한다.
5. 화면에 과일 3종의 요약 카드가 나타난다.
6. 사용자는 각 카드를 펼쳐 맛·영양, 고르는 법, 보관법, 레시피를 확인한다.
7. 필요하면 제철 캘린더나 FAQ 섹션으로 이동한다.

## 4. 화면 구조

서비스명은 `제철한입`으로 사용한다.

### 고정 헤더와 메뉴

- 로고와 서비스명
- 홈, AI 추천, 제철 캘린더, 이용 안내 메뉴
- 모바일에서는 메뉴 버튼으로 접고 펼친다.

### 홈

- 제철 과일을 고르는 서비스의 가치를 설명하는 Hero 영역
- 추천 섹션으로 이동하는 주요 버튼
- 계절감을 주는 과일 일러스트와 짧은 안내 문구

### AI 과일 추천

- 날짜 입력 필드와 추천 버튼
- 입력 오류, 로딩, 성공, 실패 상태를 같은 영역에서 명확히 표시
- 과일 3종 카드
- 카드 기본 영역에는 과일명, 이모지, 제철 이유 요약을 표시
- 펼침 영역에는 맛·영양, 고르는 법, 보관법, 레시피를 표시

### 제철 캘린더

- 1월부터 12월까지 월별 대표 과일을 확인하는 카드 또는 칩 목록
- 추천 API와 동일한 월별 후보 데이터를 사람이 읽기 쉬운 형태로 표시

### 이용 안내·FAQ

- 한국 국내 유통 기준임을 안내
- 제철 시기는 품종, 산지, 기후에 따라 달라질 수 있음을 안내
- AI 설명은 건강 진단이나 치료 조언이 아님을 안내
- API 오류와 재시도 방법을 안내

## 5. 시각 및 반응형 설계

- 크림색 배경에 주황, 초록, 붉은색을 포인트로 사용하는 따뜻한 마켓 분위기
- 시스템 글꼴을 우선 사용해 별도 폰트 다운로드 없이 빠르게 표시
- 과일 이모지와 CSS 장식을 중심으로 구성해 이미지 파일 의존성을 최소화
- 360px 모바일에서는 카드 1열, 768px 태블릿에서는 2열, 1280px 데스크톱에서는 3열 구성
- 키보드만으로 메뉴, 날짜 입력, 버튼, 펼침 카드를 조작할 수 있게 구현
- 상태 메시지에 `aria-live`를 적용하고 포커스 표시와 색상 대비를 확보

## 6. 시스템 구성

예상 파일 구조는 다음과 같다.

```text
A1-3/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
├── api/
│   ├── recommend.py
│   └── seasonal_data.py
├── docs/
│   └── service-plan.md
├── .env.example
├── .gitignore
├── requirements.txt
├── vercel.json
└── README.md
```

각 구성 요소의 책임은 다음과 같다.

- `index.html`: 의미 구조, 메뉴, 입력 폼, 결과·상태 영역
- `css/style.css`: 디자인 토큰, 레이아웃, 반응형 스타일, 애니메이션
- `js/app.js`: 메뉴, 폼 검증, `fetch`, 타임아웃, 상태 전환, 안전한 결과 렌더링
- `api/seasonal_data.py`: 월별 제철 과일 후보와 기본 설명 데이터
- `api/recommend.py`: 요청 검증, 후보 선택, AI 호출, 응답 검증, 오류 변환
- `docs/service-plan.md`: 목적, 대상, 화면, AI 입력·출력·실패 처리 기준

## 7. 추천 방식

월별 제철 후보는 서버 코드에 명시적으로 관리한다. 서버가 입력 날짜의 월을 기준으로 후보를 선택한 뒤, AI는 후보 이외의 과일을 새로 추천하지 않고 제공된 후보를 설명하는 역할만 맡는다.

이 혼합 방식은 AI만으로 과일을 선택할 때 발생할 수 있는 계절 불일치를 줄이고, 고정 문구만 제공하는 방식보다 풍부하고 자연스러운 정보를 제공한다.

## 8. API 계약

### 요청

`POST /api/recommend`

```json
{
  "date": "2026-08-29"
}
```

서버는 문자열 형식뿐 아니라 실제 존재하는 날짜인지 검증한다.

### 성공 응답

```json
{
  "date": "2026-08-29",
  "month": 8,
  "source": "ai",
  "fruits": [
    {
      "name": "복숭아",
      "emoji": "🍑",
      "season_reason": "여름철 풍미가 좋은 대표 과일입니다.",
      "taste_nutrition": "달콤하고 과즙이 풍부합니다.",
      "selection_tip": "향이 나고 표면에 상처가 적은 것을 고르세요.",
      "storage_tip": "먹기 직전에 짧게 냉장 보관하세요.",
      "recipe": "복숭아 요거트 볼"
    }
  ],
  "notice": "제철 시기는 품종과 산지에 따라 달라질 수 있습니다."
}
```

`fruits`는 정확히 3개여야 하며 모든 필드는 비어 있지 않은 문자열이어야 한다. AI 응답은 JSON 코드 펜스를 제거한 뒤 이 구조로 검증한다.

### 실패 응답

```json
{
  "error": {
    "code": "INVALID_DATE",
    "message": "올바른 날짜를 입력해 주세요."
  }
}
```

- `400`: 본문 누락, 빈 날짜, 잘못된 날짜 형식
- `405`: 지원하지 않는 HTTP 메서드
- `500`: 환경변수 누락 또는 예상하지 못한 서버 오류
- `502`: AI API의 인증, 쿼터, 네트워크, 응답 형식 오류

오류 응답이나 로그에는 API 키와 AI 요청 인증 헤더를 포함하지 않는다.

## 9. AI 호출과 복구

- 환경변수 `COPA_API_KEY`를 서버에서만 읽는다.
- A1-2와 같은 Codyssey OpenAI 호환 Chat Completions 엔드포인트와 `gpt-5.4-mini` 모델을 사용한다.
- 시스템 프롬프트는 제공된 후보 3종만 사용하고 지정된 JSON 구조만 반환하도록 제한한다.
- 첫 응답이 JSON 구조를 만족하지 않으면 한 번만 교정 요청한다.
- 교정까지 실패해 AI 응답 구조만 복구할 수 없으면 서버의 기본 설명 데이터로 과일 3종을 반환한다.
- 인증, 쿼터, 네트워크 등 AI API 호출 자체가 실패하면 `502` 오류를 반환해 프론트가 재시도를 안내한다.
- 기본 설명을 사용한 응답은 `source`를 `fallback`으로 설정하고 사용자에게 AI 상세 설명을 불러오지 못했다는 안내를 함께 제공한다.

이 복구 전략 덕분에 핵심 추천은 유지되지만, 실제 AI 호출이 성공한 것처럼 오해하지 않도록 출처를 명확히 구분한다.

## 10. 프론트엔드 상태 처리

- 빈 입력: 요청을 보내지 않고 날짜 입력을 안내
- 요청 중: 버튼을 비활성화하고 로딩 문구와 애니메이션 표시
- 성공: 이전 오류를 지우고 과일 카드 3개 표시
- 기본 결과: 카드와 함께 AI 설명을 불러오지 못했다는 안내 표시
- 서버 오류: 상태 코드와 무관하게 사용자에게 안전한 한국어 안내 표시
- 타임아웃: `AbortController`로 20초 후 요청을 중단하고 재시도 안내
- 재요청: 이전 요청의 상태와 결과를 정리한 뒤 새 요청 시작

결과 텍스트는 `innerHTML`로 직접 삽입하지 않고 DOM 노드를 생성해 `textContent`로 렌더링한다.

## 11. 보안 및 운영

- `.env`는 Git에 포함하지 않고 `.env.example`에는 변수명과 예시 값만 기록한다.
- 브라우저는 AI API를 직접 호출하지 않는다.
- README와 화면 캡처에 실제 API 키를 포함하지 않는다.
- Vercel 프로젝트 환경변수로 `COPA_API_KEY`를 등록하도록 문서화한다.
- 과금과 쿼터를 고려해 추천 버튼을 요청 중 비활성화하고 자동 반복 호출을 만들지 않는다.

## 12. 수동 검증 및 제출 자료

사용자 요청에 따라 자동화 테스트 파일은 만들지 않는다. 구현 후 다음 항목을 수동으로 확인한다.

- 정상 날짜 입력이 AI 또는 명시된 기본 결과로 이어지는지
- 빈 입력, 잘못된 날짜, API 오류, 20초 타임아웃 안내가 보이는지
- 홈, AI 추천, 제철 캘린더, 이용 안내 메뉴 이동이 동작하는지
- 360px 모바일과 1280px 데스크톱에서 레이아웃이 깨지지 않는지
- 키보드 조작, 포커스 표시, 상태 메시지 읽기 보조 속성이 동작하는지
- 프론트 소스와 생성물에 API 키가 포함되지 않았는지

제출 시 데스크톱 화면, 모바일 화면, AI 추천 성공 화면을 캡처한다. AI 코딩 도구 사용 과정은 현재 대화 로그 또는 별도 스크린샷으로 준비한다.

## 13. 완료 기준

- 메뉴로 이동 가능한 4개 섹션이 있다.
- 날짜 입력에서 과일 3종 결과까지의 전체 상호작용이 동작한다.
- Python Serverless Function이 AI API를 호출하고 안전한 구조의 JSON을 반환한다.
- 빈 입력, API 오류, 타임아웃을 사용자에게 한국어로 안내한다.
- 모바일과 데스크톱에서 정상 표시된다.
- README와 서비스 기획서가 구현 내용과 일치한다.
- API 키가 코드, Git 이력, README, 화면에 노출되지 않는다.
